# 通知拦截 App 灰白玻璃 UI 重设计

## 目标

将现有偏工程样板的 Material 默认界面，重设计为清新、克制、灰白主调的移动端工具界面。新界面要保留现有功能，不新增业务能力，不改变规则优先级和拦截逻辑。

设计关键词：

- 灰白主调
- 半透明玻璃质感
- 清爽、轻量、可信赖
- 图标辅助识别
- 适合高频查看和管理通知历史

## 范围

本次改版包含以下页面和通用组件：

- 历史页
- 应用页
- 规则页
- 设置页
- 涂抹选词页
- 底部导航
- 通用玻璃卡片、状态标签、页面标题、App 标识、图标系统

本次不包含：

- 新增拦截规则类型
- 修改规则优先级
- 新增 Shizuku 或系统级增强能力
- 改动通知监听、拦截、历史写入等核心业务逻辑

## 视觉系统

### 颜色

主背景使用冷灰白，页面整体保持低饱和：

- 背景：`#F6F7F8`
- 主要玻璃卡片：半透明白色，如 `#FFFFFF` 88% 透明度
- 卡片边框：`#FFFFFF` 与浅灰边框叠加，形成轻薄玻璃边缘
- 主文字：`#1F2933`
- 次文字：`#69727D`
- 弱文字：`#9AA3AD`

状态色保持柔和，只在有意义的位置出现：

- 已拦截 / 黑名单：雾红
- 放行 / 白名单：雾绿
- 系统放行：冷灰蓝
- 当前选中：浅灰绿
- 已添加词：浅灰并降低文字透明度

### 玻璃质感

玻璃质感通过以下组合实现：

- 半透明白底
- 细描边
- 柔和阴影
- 层级清晰的间距
- 必要时使用轻度 blur，但不依赖重度模糊，避免 Android 端性能和可读性问题

卡片不做过度圆角，保持 8 到 16dp 范围。工具栏、底部导航可稍大圆角以体现悬浮玻璃感。

### 字体与间距

沿用 Compose Material 3 字体体系，但重新定义层级：

- 页面标题：醒目但不过大
- 卡片标题：中等字重
- 正文：优先可读
- 时间、包名、命中说明：更小、更轻

间距遵循 8dp 网格：

- 页面外边距：16dp
- 卡片内边距：16dp 到 20dp
- 卡片间距：12dp
- 内容组间距：8dp、12dp、16dp

## 图标系统

各功能都需要配对应图标，避免现在底栏用文字首字代替图标的粗糙感。

建议使用 Material Icons 或 Compose 内置可用图标；如果项目依赖不支持某些图标，选择语义接近的替代图标，不引入复杂图标库。

底部导航：

- 历史：History / Schedule
- 应用：Apps / GridView
- 规则：Rule / Tune / Shield
- 设置：Settings

状态与操作：

- 已拦截：Block / Shield
- 已放行：CheckCircle
- 系统放行：Verified / AdminPanelSettings
- 白名单：CheckCircle / VerifiedUser
- 黑名单：Block / GppBad
- 命中关键词：Bolt / Sell
- 标记：Edit / Gesture
- 返回：ArrowBack
- 添加白名单：PlaylistAddCheck
- 添加黑名单：PlaylistRemove / Block

页面分组：

- 默认规则：Shield
- 增强规则：AutoAwesome / Tune
- 我的规则：ListAlt
- 通知权限：NotificationsActive
- 系统限制说明：Info

## 页面设计

### 历史页

历史页是首屏核心，应从“能快速判断最近发生了什么”出发。

结构：

1. 顶部页面标题：`历史`
2. 玻璃状态概览：今日通知、已拦截、已放行
3. 分段筛选：全部 / 拦截 / 放行
4. 通知历史列表，默认平铺

通知卡片：

- 左侧显示圆形 App 标识，优先用 App 图标；如果当前实现暂时拿不到图标，则用 App 名首字或包名首字生成灰白圆形标识。
- 右侧第一行显示 App 名和时间。
- 第二行显示通知标题。
- 第三行显示通知正文，两到三行内截断。
- 底部显示状态标签和操作按钮。
- 被拦截通知必须显示 `命中：关键词`，例如 `命中：优惠券`。
- `标记` 操作用图标按钮加文字，点击直接进入涂抹选词。

视觉重点：

- 被拦截不使用大面积红色，只用小型雾红状态标签。
- 放行项保持安静，避免和拦截项抢视觉。
- 列表要适合长时间扫读。

### 应用页

应用页用于按 App 查看通知情况。

结构：

1. 页面标题：`应用`
2. 应用统计列表

应用卡片：

- 左侧 App 标识。
- 主标题为 App 名。
- 副信息显示 `通知 X 条 · 拦截 Y 条`。
- 如果有最近命中词，展示柔和标签 `最近命中：xxx`。
- 右侧可放一个轻量箭头或统计图标，但当前不新增详情页功能。

### 规则页

规则页需要让用户理解“系统优先、白名单优先”的规则关系，但不新增复杂说明页。

结构：

1. 页面标题：`规则`
2. 规则优先级提示卡：系统级优先、白名单优先
3. 默认规则卡
4. 增强规则卡
5. 我的规则列表

规则卡片：

- 默认规则显示为关键词 chips，避免长文本堆成一坨。
- 增强规则使用图标、标题、开关和一句风险提示。
- 我的规则中，白名单和黑名单用不同柔和标签区分，并标明作用范围：全局 / 当前 App。

### 设置页

设置页改成玻璃分组列表。

结构：

1. 页面标题：`设置`
2. 通知监听权限状态
3. Android 系统限制说明
4. Shizuku 增强模式占位说明

每项使用图标 + 标题 + 说明文字。文字保持中文正常显示，避免乱码。

### 涂抹选词页

涂抹选词页是最有特色的交互，需要比普通列表更精致。

结构：

1. 顶部栏：返回按钮、标题 `涂抹选词`
2. 来源通知玻璃卡：App 名、标题、正文
3. 文字格子区域
4. 底部固定玻璃操作栏：添加白名单、添加黑名单

文字格子：

- 每个文字或词块为一个圆角玻璃小块。
- 未选中：白色半透明
- 已选中：浅灰绿
- 已添加：浅灰、文字降低透明度、不可再次点击
- 非连续选择仍由现有逻辑视为多个词，连续选择视为一个词。

操作：

- 点击添加白名单时弹窗选择：全局白名单 / 仅当前 App 白名单。
- 点击添加黑名单时按现有范围处理。
- 添加完成后不返回上一页，已添加词置灰，用户可继续二次涂抹。

## 组件设计

建议新增或重构以下 UI 组件：

- `GlassCard`：统一玻璃容器样式。
- `GlassSurface`：页面背景和大块容器。
- `StatusPill`：状态标签，支持图标和文本。
- `PageHeader`：页面标题、说明和可选统计。
- `AppAvatar`：App 图标或占位标识。
- `IconLabelButton`：图标 + 文字按钮。
- `GlassBottomBar`：半透明底部导航。

这些组件只负责视觉和布局，不持有业务状态。

## 数据与业务逻辑

本次 UI 改版复用现有数据：

- `NotificationRecord`
- `AppSummary`
- `RuleItem`
- `NotificationDecision`
- `RuleScope`

业务逻辑不变：

- 系统级规则优先
- 白名单优先
- 黑名单与默认营销词用于拦截
- 被拦截通知显示命中关键词
- 涂抹选词的连续 / 非连续分组规则保持现状

## 测试与验证

实现后需要验证：

- `testDebugUnitTest` 通过。
- Debug APK 可构建。
- 真机安装成功。
- 历史页、应用页、规则页、设置页、涂抹页中文不乱码。
- 底部导航有对应图标。
- 被拦截通知显示命中关键词。
- 涂抹选词添加后已添加词置灰且不返回。
- 小屏幕下文字不重叠，按钮不溢出。

## 风险

- Android 真机玻璃模糊效果性能不稳定，因此玻璃感主要通过半透明、描边和阴影实现。
- App 图标获取可能需要额外工具函数；如果本轮不做真实图标提取，先使用首字占位，但组件接口保留未来替换空间。
- 现有源码中的中文显示存在乱码，需要在 UI 改版时统一修正。
